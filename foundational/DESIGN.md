# DESIGN — Bookkeeper

The design system and brand rules for `apps/web`. **Load the `/frontend-design` skill before any UI work** (`.claude/skills/frontend-design`). Load `dataviz` before any chart work. Log every decision or deviation in the decisions log at the bottom of this file.

## Brief

- **Subject:** a joint household account for two people, replacing the "Joint Account Workbook" spreadsheet. The money is Australian dollars, and the financial year runs 1 July – 30 June.
- **Audience:** two partners. Most days it's a quick look on a phone ("did the power bill come out?"). At month-end it's a desktop session reconciling everything.
- **Job:** answer _"are we OK this month, and what's coming?"_

Every screen answers exactly one question:

| Screen                                    | Question                            |
| ----------------------------------------- | ----------------------------------- |
| Dashboard                                 | Are we OK?                          |
| Monthly                                   | What's in and out this month?       |
| Bills, Subscriptions, Expenses, Utilities | What do we pay for?                 |
| A single item's detail page               | Is this one costing more over time? |
| Income                                    | What came in?                       |

If a section doesn't help answer its screen's question, it belongs somewhere else.

## Concept: "Polymer"

The palette is taken from Australian polymer banknotes, the material this money is actually made of. The ground is a faint green-grey, like clear polymer: not cream, not navy, not black. Banknote colours are used sparingly, and each means exactly one thing:

- **Violet ($5 note):** interactive elements only.
- **Green ($100):** money coming in.
- **Gold ($50):** something needs attention.
- **Red ($20):** something is wrong.

Money going out, which is most of what's on screen, stays plain ink. The colour that does appear therefore always means something. (The one enrichment: a detail page's trend chart draws its series in the item's own identity colour - a category or person colour already shown elsewhere on that page - rather than ink; see Patterns → Charts.)

Directions rejected, and why:

- **The previous indigo-on-slate:** it was the Tailwind default look.
- **Ink and lamp-amber:** that's home-work-hours-tracker's identity.
- **Cream with a serif:** the generic "finance" default.

## Colour

Tokens live in `src/routes/layout.css`. They are mapped onto the shadcn-svelte variables:

- `--background` = ground
- `--card` / `--popover` = surface
- `--foreground` = ink
- `--primary` / `--ring` = violet
- `--border` = rule
- `--destructive` = over

The brand names are also exposed as Tailwind colours (`bg-ground`, `text-in`, `bg-due/15`, …).

| Token     | Light     | Dark      | Role                                                                      |
| --------- | --------- | --------- | ------------------------------------------------------------------------- |
| `ground`  | `#F2F5F3` | `#101613` | Page background (polymer)                                                 |
| `surface` | `#FFFFFF` | `#18201C` | Cards, sheets, menus, popovers                                            |
| `ink`     | `#16201B` | `#E5ECE8` | Text, and money going out                                                 |
| `muted`   | `#5C6A63` | `#93A299` | Secondary text, meta                                                      |
| `rule`    | `#DAE1DC` | `#27322C` | Borders and dividers                                                      |
| `violet`  | `#5B3FA0` | `#B7A1EC` | Buttons, links, focus, selection. **Interactive elements only**           |
| `in`      | `#0A6B50` | `#3FC79D` | Money coming in, surplus                                                  |
| `due`     | `#7A5600` | `#E6AE34` | Due soon; estimated or assumed values. Text in `due` sits on a `due` tint |
| `over`    | `#9C3320` | `#F2735A` | Overdue, deficit, delete                                                  |

- Each person's `displayColor` (Settings) remains their per-person colour in Income, Subscriptions and charts.
- Contrast is validated with axe and screenshots (Phase 1). Light-mode `in`, `due` and `over` are all darker than the literal $100/$50/$20-note hues DESIGN.md started from, in two rounds: first checked as plain text against `ground` (the literal notes' green/gold/red only hit 4.84:1/3.13:1/5.00:1 there - the gold outright failed WCAG AA's 4.5:1), then checked _again_ with axe against real rendered badges once Phase 1 actually built them, which is a different (and stricter) test than text-on-`ground` - see the next entry.

### Status is never shown by colour alone

| State             | Colour  | Also shown by                         |
| ----------------- | ------- | ------------------------------------- |
| Overdue           | `over`  | Alert icon plus "3 days overdue"      |
| Due soon          | `due`   | Clock icon plus "Due in 4 days"       |

## Type

The whole app uses one variable superfamily, **Recursive** (Arrow Type), self-hosted: no external font requests, which keeps the CSP clean. Its axes are assigned roles:

| Role    | Setting                               | Used for                                                  |
| ------- | ------------------------------------- | --------------------------------------------------------- |
| Display | `CASL 1`, wght 750, `slnt -4`         | Page titles and the month strip's headline figure only    |
| UI/body | Sans Linear, `CASL 0`, wght 400 / 560 | Everything else                                           |
| Figures | `MONO 1`, `CASL 0`, `tabular-nums`    | Every money value and table date, right-aligned in tables |

- **Why:** the casual display cut reads like the partners writing in the household book, and the mono figures read like the spreadsheet it replaced. One file makes the pairing coherent and cheap.
- **Open risk:** if the Linear sans reads too quirky in dense 14px tables, only the UI/body role switches to **Hanken Grotesk**. Decide from Phase 1 screenshots and log it below.
- **Scale (1.2 ratio):** 12 / 13 / 14 (UI base) / 16 / 20 / 24 / 30 / 40px. 40px is reserved for the month strip figure.
- **Line-height:** 1.5 for body, 1.15 for display.

### Copy rules

- Sentence case everywhere. No all-caps eyebrows, no middle-dot meta strings (use badges), no `→` suffixes on links or buttons.
- Buttons are verb-first and say exactly what happens: "Add bill", "Save changes", "Log payment".
- Lifecycle verbs are fixed, and the toast repeats the verb:

  | Action    | Toast             |
  | --------- | ----------------- |
  | Pause     | "Bill paused"     |
  | Resume    | "Bill resumed"    |
  | Archive   | "Bill archived"   |
  | Unarchive | "Bill unarchived" |
  | Restore   | "Bill restored"   |
  | Delete    | "Bill deleted"    |

  "Unpause" is retired in favour of Resume.

- Errors say what to fix ("Enter an amount"). They never apologise and are never vague.
- Empty states invite action: "No bills yet. Add the first one to see when it's due."

## Layout

- Content column: `max-w-5xl`. The Dashboard (`/`) widens to `7xl` (nav bar included) via the `ROUTE_WIDTHS` map in `+layout.svelte`, which is where any other wider route is added so its stat row and chart/detail split use the desktop width.
- Cards are `surface` with a `rule` border and **no shadow**. Only floating surfaces (menus, popovers, sheets, dialogs) get elevation.
- Radius: 10px for cards and sheets, 6px for controls, full for badges and chips. Radii are not all the same.
- **Mobile lists** (below `sm`): every list is a two-line row with a 48px minimum height:
  - Left: the name on top, meta badges underneath.
  - Right: the amount on top, the due chip underneath.
  - Far right: the ⋮ menu.
- At `sm+` the same data renders as a real table. **One row component drives both.** Never write parallel desktop and mobile markup.
- Lifecycle groups (Paused, Archived, Removed) sit behind Tabs with counts, not uppercase section rows.
- Adding and editing happen in a **Sheet** (desktop) or **Drawer** (mobile), never in an inline table row. Clicking a row opens its detail page.

### Motion

- Sheets, drawers and menus use bits-ui's default transitions.
- Nothing else animates. `prefers-reduced-motion` disables all of the above.

## Retired: the month strip

A horizontal ▲/▼ timeline of the current month, with a running-balance
line, was tried as both Monthly's and the Dashboard's hero. It was widely
disliked and has been thrown away everywhere: PLAN_02 Phase 1 replaced
Monthly's strip-plus-two-tables layout with one chronological list (see
Patterns → Monthly's unified list, below), and Phase 2 replaced the
Dashboard's strip with a two-zone "Right now"/"Over time" snapshot (see
Patterns → Charts, and `routes/+page.svelte`). `MonthStrip.svelte` and
`$lib/month-strip.ts` are deleted; nothing in this app builds a day-of-month
timeline any more.

## Interaction rules

- Every floating surface (menu, popover, tooltip, select) is **portalled and collision-aware** via bits-ui, so it is never clipped by a scrolling card and flips upward near the viewport edge.
- The same row-action menu (`ActionMenu`) is used on mobile and desktop.
- Destructive actions confirm through an AlertDialog, never `confirm()`.
- Mutations confirm with a Sonner toast. Inline errors are only for form validation.
- Focus is always visible: a 2px `violet` ring.

## Components

- Primitives come from **shadcn-svelte**, vendored in `src/lib/components/ui/**`, generated by the CLI (`pnpm dlx shadcn-svelte@latest add <name> -y`, config in `apps/web/components.json`). Wrap and compose them. Don't edit `ui/**` beyond what the CLI generates. `ui/**` is excluded from coverage.
- App-level compositions live in `src/lib/components/` (and `src/lib/components/app/` from Phase 1). Icons for app code: `@mdi/js`. The vendored components use `@lucide/svelte` internally.

## Patterns

Code-level conventions the design system relies on. They live here (rather than only in the code) so a new screen reaches for the existing machinery instead of re-deriving it.

### Charts

- **Hand-rolled inline SVG components in `src/lib/components/`** — no charting library. The set is `MonthlyExpenseChart.svelte`, `NetPositionTrendChart.svelte`, `IncomeYtdChart.svelte`, `YearlyIncomeLineChart.svelte` and `PieChart.svelte`.
- **Shared y-axis maths**: `src/lib/chart-utils.ts`'s `niceMax(value)` gives a round ceiling and step across four gridlines for an all-positive domain; `niceDomain(min, max)` is the same idea for an axis that may need to dip below zero (e.g. `NetPositionTrendChart`'s net-position line over income/expense bars) - it always includes zero in the returned range. Every bar/line chart uses one of these; don't re-declare local scale maths.
- **SVG recipe**: a fixed logical `viewBox` (`720×240` bar/line, `180×180` pie) on a `class="w-full"` svg so it scales to any width. `role="img"` plus an `aria-label` describing the chart, written `aria-label={ariaLabel}` (Svelte doesn't camelCase shorthand props into `aria-*` attributes).
- **Theme-aware colours** come from `themeState.current` as a light/dark hex pair. Series colours passed in as data are fixed mid-tone hexes that read on both themes; money going out is ink, money in is `in`. A derived total that isn't itself an in/out value (`NetPositionTrendChart`'s net line) is plain ink too, the same treatment the old month strip's running-balance line used.
- **Detail-page trend charts carry the item's identity colour**: `MonthlyExpenseChart` takes an optional `color` prop, and each outgoing adapter declares it via `chartColor(item, ctx)` - the same category colour (Bills/Expenses) or owner `displayColor` (Subscriptions, preferring the owner over the category) its stat row already shows as a `dot`, so the line always matches something already on the page. Utilities have no user-selectable colour (their category is the fixed system "Utilities" one), so they, and any uncategorized item, fall back to a neutral series accent - the unassigned $10-note blue (`#0E6FA8` light / `#4FA6D9` dark). Money _figures_ (the latest-value label, the tooltip) stay plain ink; only the series line/area/point take the colour.
- **Legends**: a `text-xs` row of swatch + label above bar/line charts, or a right-hand `<ul>` of value + rounded percentage for pies. The donut is a fixed `180px` `shrink-0` element and the legend `min-w-40 flex-1` inside a `flex flex-wrap items-center justify-center` root, so the legend wraps below on narrow cards and sits beside the donut on wide ones. Pies show the formatted total in the centre by default; a caller can override it with a `center` snippet.
- **Empty states**: `"Not enough data yet"` for bar/line charts, or a caller-supplied `emptyMessage` prop on `PieChart` ("No income logged this year").
- **Netting is the caller's job, not the chart's**: pages derive net slices/series and pass already-net numbers in. The Dashboard's total is netted server-side in `apps/api/app/services/income_netting.ts` (same rule as the Income page's client-side net of tax), so the two never disagree.
- **Placement**: Income's charts live in a `Card` accordion below the entries table, collapsed by default, with a chevron header button (`aria-expanded`). Chart data is fetched lazily the first time the section opens for a given user/year and re-fetched after any entry mutation while it's open.

### Reorderable rows (drag-and-drop)

Manually-orderable lists (Categories' sibling groups, backed by a `sortOrder` column) are reordered by click/touch-and-drag, not up/down arrow buttons — a pair of tap targets per row doesn't scale to touch, and arrows add a click per position moved instead of one drag. See `src/lib/components/CategoryTree.svelte`.

The outgoings lists (Bills, Subscriptions, Expenses, Utilities) are **not** drag-ordered: each carries a `Sort` control instead, and groups by a declared key (see below).

- **Library**: `svelte-dnd-action`'s `dragHandleZone` action on the container wrapping the reorderable group (`use:dragHandleZone={{ items, flipDurationMs: 150, dragDisabled }}`), with `onconsider`/`onfinalize` updating a local `$state` copy of the list.
- **Groups are separate zones**: a list mixing reorderable and non-reorderable groups splits them into separate zones so each zone's `items` matches its DOM children. Nested child groups get **unique `type` strings** (`'top'` / `'system-top'` / `` `children-${parentId}` ``) so the library itself refuses cross-group drops.
- **Handle**: `src/lib/components/DragHandle.svelte` — a `use:dragHandle` span rendering the six-dot `mdiDrag` icon, `cursor: grab`/`grabbing`. It is not `IconActionButton`: a drag handle isn't a click action and needs the library's action attached directly to it. Place it first on the row, in a leading slot before the colour dot and name.
- **Persisting**: `src/lib/dnd.ts`'s `reorderedSortOrders(items)` reassigns the same pool of `sortOrder` values the group already held to the new positions, returning only the `{id, sortOrder}` pairs that changed — never introducing a gap or duplicate. `sortOrder` is per sibling group, not global.
- **Keyboard**: no separate fallback is built — `dragHandleZone`/`dragHandle` support keyboard reordering natively (Tab to the handle, Space/Enter to pick up, arrows to move, Space/Enter or Escape to drop).

### List sorting and grouping

- **Sorting is adapter-declared**, not per-page: `$lib/outgoings/types.ts`'s `OutgoingSortOption` (`value`, `label`, optional `compare`) plus `sorts`/`defaultSort` on the adapter. `OutgoingsList` renders one native `Sort` `<select>` above the table; the first option (or `defaultSort`) is what the page showed before the control existed, so adding it changes nothing until the user picks something.
- **Options always include "Name (A-Z)"** plus page-relevant metrics. Comparators come from `$lib/outgoings/sort.ts` (`byName`, `byValueAsc`, `byValueDesc`) rather than being re-derived per adapter; missing values always sort last.
- **The choice is remembered per page** in `localStorage` under `outgoings-sort:<adapter.kind>`, falling back to the default if the stored value is no longer offered.
- **Grouping is adapter-declared and on by default**, matching Bills' existing frequency groups: an `OutgoingGrouping` object (`byLabel`, `key`, optional `order`/`label`) on the adapter. Bundling the four fields means grouping can't be declared without the toggle's noun. Bills and Utilities group by frequency, Expenses by category (`order`/`label` resolve names and order from the loaded categories; `key` is context-aware, so an expense whose category is null _or_ hidden - archived/soft-deleted, and absent from the loaded lookups - folds into the single "Uncategorized" group its row already shows). Subscriptions aren't grouped - they're already scoped to one person. Groups render as muted section rows, distinct from the lifecycle tabs above them.
- **Grouping can be turned off** with the `Group by <noun>` toggle beside the sort control (`byLabel` supplies the noun, e.g. "Group by category"; the vendored `Toggle`'s pressed state reads as on/off); the list then renders flat. Like the sort, the choice is remembered per page under `outgoings-group:<adapter.kind>` - only an explicit "off" disables it, so the default is on.
- **The sort applies within each group** (and within the selected lifecycle tab), so grouping and sorting compose rather than fighting.
- **Expenses' old drag reorder is gone.** `sortOrder` remains on the row but is no longer editable in the UI, so its list defaults to Name (A-Z) instead of the frozen manual order.

### Category tree

- Categories support one level of nesting (`parent_id` → `parent_id` is rejected server-side, so no grandchildren). `src/lib/components/CategoryTree.svelte` renders one drag-reorderable zone of top-level rows; a row with children gets a chevron button (`mdiChevronRight`/`mdiChevronDown`, `aria-expanded`) toggling a nested children zone indented over a muted band.
- Everything is open by default; the page header offers an "Unfold less"/"Unfold more" toggle that collapses/expands every parent.
- The add/edit form's "Parent" `<select>` (`CategoryFormSheet.svelte`) uses **string** option values (`value={String(parent.id)}`) because Svelte's `bind:value` compares against the option's `__value`, so numeric options never match a string-bound state. A category with children can't itself be demoted to a child, so its parent select renders `disabled`.
- Children are full categories — `CategorySelect` indents them under their parent in other forms.

### Responsive tables

Every data table reflows into stacked cards below `sm` (640px) instead of scrolling horizontally — the app is mobile-first. One `{#each}`, one set of `<tr>`/`<td>` elements, restyled per breakpoint. **Never write parallel desktop and mobile markup.** `src/lib/outgoings/OutgoingsList.svelte` and `OutgoingDetail.svelte`'s payment history table are the fullest worked examples. (Monthly's own tables were retired for a single chronological list — see Patterns → Monthly's unified list, below.)

- **`table`**: `block w-full border-collapse text-sm sm:table`. **`thead`**: `hidden sm:table-header-group`. **`tbody`**/**`tfoot`**: `block sm:table-row-group` / `block sm:table-footer-group`.
- **The wrapping `Card`**: pass `pivotTable` so its chrome (background, border, radius) is unset below `sm`; each `<tr>` then carries its own card background (`bg-card`) on mobile and returns it to the card via `sm:bg-transparent`.
- **A data `<tr>`** becomes a bordered card on mobile, a normal row on desktop: move the row's divider classes behind `sm:` and add the mobile card classes (`mb-2 block rounded-lg border bg-card last:mb-0 … sm:table-row sm:rounded-none sm:border-0 sm:border-b …`).
- **Every `<td>`** gets `sm:table-cell`. A cell whose column has a visible `<th>` label becomes `flex items-center justify-between gap-3 px-3 py-2 … sm:table-cell` with the label prepended as `<span class="text-muted-foreground shrink-0 text-xs sm:hidden">Label</span>` - sentence case, not an all-caps eyebrow (see Copy rules). A multi-control cell (e.g. Cadence) uses a stacked block instead. The actions cell is `flex justify-end gap-1 … sm:table-cell sm:text-right` with no label. A genuinely empty cell is `hidden sm:table-cell`.
- **Fixed-width inputs** (`w-24`, `w-40`, …) become `w-full … sm:w-24` so they fill the mobile card and match at `sm:` and up.

### Monthly's unified list

Monthly (`src/lib/components/monthly/MonthlyUnifiedList.svelte`) replaces
the old month strip plus two responsive tables (Outgoing, Incoming) with
one chronological, always-vertical list - bills and income entries/
placeholders interleaved by resolved date. Unlike the Responsive tables
pattern above, this list does **not** pivot into a `<table>` at `sm+`: it
stays a single two-line row shape (DESIGN.md's Mobile lists rule, applied
at every width) since the whole point is one continuous chronological feed,
not a data grid. The merge itself is a pure, unit-tested `$lib` helper
(`monthly-unified-list.ts`'s `buildUnifiedList`), keeping the sort/tie-break
logic out of the component.

- **Ordering**: outgoing lines sort by `resolveDueDate`; a logged income
  entry sorts by its `receivedOn`; a placeholder pay date sorts by its own
  date. Items with no resolvable date sort last, in their original
  (pre-sort) order - the same tie-break `+page.svelte`'s old
  `sortedExpenseLines` used, generalized to the merged list.
- **A "Today" divider** sits between the last past/today item and the first
  future one (or right before the undated tail if every dated item is
  already in the past); the list scrolls to it on mount, respecting
  `prefers-reduced-motion`. An item landing exactly on today's date also
  gets a `bg-in-tint` row highlight.
- **Row shape is lead → main → figures → trailing actions**, left to right:
  a 44px leading icon (the Paid checkbox for a bill, a static check glyph
  for a logged income entry, or an empty 44px spacer for a placeholder, so
  every row's label starts at the same x-position), the label plus a status
  line (due chip / received date+owner+note / "Not yet logged"), the
  amount(s) right-aligned, then the row's action button(s). Matches the
  owner-approved Artifact prototype explored in PLAN_02_OVERVIEW.md - an
  earlier pass put the checkbox/pencil trailing instead (mirroring the old
  table's column order) and was corrected once compared against the
  prototype (see the decisions log).
- **Deliberate scope cut**: the list only ever renders `incomeRowsForLine`'s
  rows (`actual`/`placeholder`) - the old `IncomingTable`'s per-line summary
  row (showing a source's own projected/actual even with nothing dated to
  show) is gone. A source with no pay dates and no logged entries this
  month simply has nothing in the list, though its totals still count
  toward `data.income.actualTotal`/`projectedTotal` and the stat row above.
- **Touch targets are ≥44px** here specifically (Paid checkbox, edit
  pencil, Accept/Edit) - a deliberate deviation from the Quality floor's
  general exemption for inline row `IconActionButton`s, because these
  particular controls get tapped on this page more than almost anywhere
  else in the app. `IconActionButton`'s default `size-8` is overridden with
  a `size-11` class (merged via `cn`/`twMerge`, which lets a later utility
  win a same-group conflict); the checkbox itself stays visually `size-4`
  inside a `size-11` tappable `<label>`.
- **No footer totals**: the old tables' Projected/Actual footer row is
  dropped - a single interleaved list has no natural place for two
  separate subtotals, and the stat row above already carries the actual
  (not projected) aggregate figures (Income, Outgoing, Net).

### Placeholder rows

A row for a known-but-not-yet-confirmed item (`MonthlyUnifiedList`'s placeholder branch — a source's projected pay date with no logged entry) uses the normal row shape plus `italic` on the `<li>` and the muted text tier on every cell. Actions are Accept (`mdiCheckBold` on the `success` variant — logs the row immediately at its projected amount/date, no confirmation) plus the normal Edit pencil; there is no Delete, because nothing is persisted yet. Reuse this shape for any future "known but unconfirmed" row rather than inventing a new muted-row treatment.

### Row actions and tooltips

- **More than two row actions use `ActionMenu`** (`src/lib/components/ActionMenu.svelte`), not a row of inline `IconActionButton`s — a single `mdiDotsVertical` trigger opening one icon+label button per action. Pass `label` (the bare verb) plus `actions` objects (`{ label, path, variant, onclick, disabled? }`). Two inline icon buttons (e.g. an inline edit's Save + Cancel) are still fine. This is a desktop-column concern; a mobile card that already condenses actions into its title row can keep inline icons past two. See `src/lib/outgoings/OutgoingsList.svelte`.
- **Icons** come from `@mdi/js` path constants, passed to `IconActionButton`'s `path` prop. Labels are always row-specific (`label="Edit {row.category.name}"`, not `"Edit"`) so a screen reader can tell one row's button from another; the same string fills the `title` tooltip and `aria-label`.
- **`IconActionButton` variants** map to Polymer tokens: `neutral`/`cancel`/`muted` hover to ink, `primary` to violet, `danger` to `over`, `amber` to `due`, `success` to `in`. Only variants that mean something get a semantic colour — violet is not a generic hover accent.
- **`HelpTooltip`** (`src/lib/components/HelpTooltip.svelte`) is a click/tap-to-reveal explanation panel for when the explanation is the point, not a courtesy label. Use it at most **once per row, on the value it explains** — Monthly's estimated Actual cell, not also its Paid checkbox. It takes a row-specific `label` and the `text` shown (and set as `title`).
- **Touch targets**: the vendored dropdown item is a compact mouse-sized row, so app-level menus a thumb reaches add `$lib/components/menu-touch.ts`'s `TOUCH_MENU_ITEM` on top of it — `pointer-coarse:min-h-11` plus wider padding, so a coarse pointer gets a ≥44px row and a mouse keeps the compact sizing. Used by the bottom tab bar's Outgoings/More overlays (`nav/`) and the row `ActionMenu`.

### Forms and spacing

- Form fields in a Sheet/Drawer use shadcn `Input`/`Label` and a `flex flex-col gap-4` stack. A category picker is `CategorySelect` (its `variant` picks form-panel or compact sizing). A colour field is `type="color"`, `h-9 w-16 cursor-pointer rounded border border-input bg-transparent p-0`.
- Page content sits inside `+layout.svelte`'s `<main>` (`max-w-5xl`, with bottom padding clearing the mobile tab bar); routes never re-declare the outer max-width/padding. Login is the one exception (full-viewport centred, outside the shell).
- Section rhythm: `mt-6` for the first section after the header, `mt-8` for each subsequent one. Stat/summary grids use `StatGrid`/`StatCard` (`grid-cols-1` below `sm`, N columns at `sm` and up).
- Multi-field forms are `flex flex-wrap items-end gap-3` (or `gap-4` in Settings/Tasks); single-field quick-adds are `flex gap-2`.

### Summary strips

- **`SummaryStrip.svelte`** (`src/lib/components/app/`) is the shared three-figure summary row for Monthly (`Income`/`Outgoing`/`Net`, `variant="compact"`) and Income (`To date`/`Salary`/`Other`, `variant="roomy"`). It renders a `<dl>`: **stacked full-width label-left / amount-right rows below `sm`**, and side-by-side divided columns from `sm` up. A figure can carry a `tone` (`in`/`over`/ink), `strong`, and a `tint` cell wash (the Net cell's in/over tint).
- **It never truncates a value.** The strips it replaces were a fixed three-across grid with `truncate` on each figure; a five-figure currency amount needs ~120px but each cell only offered ~85-95px on a phone, so values clipped. Three currency figures simply don't fit across a phone width at a readable size, so below `sm` they stack (the same `grid-cols-1`-below-`sm` logic `StatGrid` already uses). Reuse this component for any new multi-figure summary row rather than re-deriving a fixed-column grid.

### Checkboxes

- Canonical: `<input type="checkbox" class="size-4 rounded" />`. `layout.css` (in `@layer base`, so `bg-*`/`border-*` utilities can still override per instance) replaces the native control - whose checked colour is the browser accent, blue - with a violet box and a tick in the surface colour (white in light mode, near-black in dark). The amber variant is a **marker class, not the Tailwind utility**: `appearance: none` makes `accent-color` inert, so `layout.css` matches the literal class `accent-due` (`input[type='checkbox'].accent-due { --checkbox: var(--due) }`) - keep that class name in sync with the CSS (Monthly's Paid checkbox on an `estimated` line). No other `accent-*` class or `border-input` does anything on a checkbox. Forced-colors mode falls back to the native control.

### Utilities monthly grid

- `UtilityBillsGrid` is a spreadsheet-style click-to-edit cell, not a table-row edit, and that is deliberate (a 12-month grid, not a list of rows). A cell's bill delete is the always-visible `IconActionButton` in its edit state — don't reintroduce a hover-revealed corner delete.

### Loading, empty and error states

- **Loading**: `LoadingSkeleton` (`src/lib/components/app/`), a bits-ui skeleton with `role="status"`.
- **Empty**: `EmptyState` (message plus an optional action), or a lone muted `<p>` for a small sub-section.
- **Error**: `ErrorMessage` — inline form validation errors, and a page-level error for a failed load. Errors say what to fix and never apologise.
- **Success**: mutations confirm with a Sonner toast, not an inline success message.

## Quality floor

- Responsive down to 360px.
- Visible keyboard focus.
- Reduced motion respected.
- Axe-clean contrast in both themes.
- App-level menu items a thumb reaches are at least 44px on coarse pointers (see **Patterns** → Row actions and tooltips). Inline row `IconActionButton`s deliberately stay compact to keep dense tables from bloating, so this floor does not cover them — a known touch gap, not a claim that every control is 44px.
- Screenshots reviewed at 390px and 1440px, light and dark, for every UI change (see AGENTS.md).
